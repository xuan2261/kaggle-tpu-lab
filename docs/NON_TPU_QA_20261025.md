## Settings write hardening and remaining risk

`Settings::save_to_path` now serializes before staging to an exclusively created
file beside the target; it writes and calls `sync_all` before closing and
renaming over `settings.json`. A failed replacement removes the staged file
and preserves the last valid destination. Regression cases cover overwriting a
valid JSON file, a target that is a directory, and a locked target on Windows.
The existing `persist_settings` mutex still commits in-memory values only
after disk persistence returns success.

This is a defense against truncated writes, **not** a full power-loss or
cross-process transaction. Remaining review items include Windows target-file
ACL preservation on replacement (a temporary file inherits its parent's ACL),
reparse-point/directory races in a writable configuration path, external writers
outside the single-instance process, and silent default fallback on malformed
JSON. Treat them as follow-up security/reliability work before a production
hardening claim; avoid widening filesystem permissions to mask a save failure.
